.topic Using the IDE,IDE
                            Using the IDE

  ARM Turbo C is an integrated development environment: you edit, compile,
  run and fix your C programs without leaving it.

  The screen has three parts:

    the {menu bar:Menus} at the top      F10 (or Alt+letter) opens it
    the desktop with the windows         edit windows, {Message window}
    the status line at the bottom        the keys you can use now

  A typical session:

    1. F3 opens a file (HELLO.C is there on your first start)
    2. edit it; F2 saves it
    3. Ctrl+F9 compiles, links and runs it ({Run})
    4. errors appear in the {Message window}: Enter goes to the line
    5. Alt+F5 shows the {user screen} with the output of the program

  Windows: F5 zooms, Ctrl+F5 moves/sizes, F6 goes to the next window,
  Alt+F3 closes, Alt+1 ... Alt+9 selects window number n, Alt+0 lists them.
  The mouse works everywhere: menus, windows, scroll bars, dialogs.

  See also: {Editor keys}, {Make}, {Menus}

.topic Run menu,Run
                                Run menu

  Run            Ctrl+F9  makes the program if a source changed ({Make}),
                          then runs it. The screen switches to the
                          {user screen}; when the program ends you are back
                          in the IDE. Alt+F5 shows what the program wrote.
  Arguments...            the command line the program gets (argv)

  Program reset, Go to cursor, Trace into and Step over belong to the
  debugger, which is not part of this version: they are shown dimmed.

  call system("MEM") to see for itself.

.topic Compile menu,Make,Compile
                             Compile menu

  Compile to OBJ  Alt+F9   compile the active edit window to NAME.O
  Make EXE file   F9       compile and link NAME.EXE, if a source or one
                           of your own header files is newer than it
  Link EXE file            link NAME.EXE from the .O files
  Build all                compile and link everything
  Information...           the statistics of the last compile
  Remove messages          clear the {Message window}

  Without a project, the program is the file in the active edit window;
  with a {project:Project menu}, it is all the files of the project and is
  called like the project. The .EXE goes next to the source, or to the
  Output directory ({Options / Directories:Options menu}).

  While compiling, the {Compiling box} counts the lines. Errors and
  warnings go to the {Message window}.

.topic Compiling box
                            The Compiling box

  Main file          the program being made
  Compiling          the file being read now (headers too)
  Lines compiled     all lines read, with the header files, and those of
                     the main file
  Warnings, Errors   so far
  Available memory   conventional memory free for your program

  At the end it says Success, Warnings or Errors: press any key. With
  errors the {Message window} opens with the first one highlighted and the
  line shown in the editor.

.topic Message window,Errors
                             Message window

  The Message window lists what the compiler said:

    Compiling HELLO.C:
   \x07Error HELLO.C 7: 'count' undeclared
    Linking HELLO.EXE:

  Up/Down moves through the messages and shows each line in its edit
  window (the line is highlighted). Enter (or a double-click) goes to the
  line in the editor; start typing to fix it. Alt+F7/Alt+F8 go to the
  previous/next message from anywhere.

  TinyCC stops a file at its first error (warnings are all listed).
  Typical messages:
    ';' expected (got 'return')     the line above lacks a ;
    'x' undeclared                  a missing declaration or #include
    undefined symbol 'foo'          (linker) a function that does not
                                    exist or is not in LIBC.A
    implicit declaration of function 'x'   (warning) missing #include

.topic C language
                            The C language

  ARM Turbo C compiles C99 (TinyCC): // comments, declarations anywhere,
  long long, inline, _Bool, designated initializers, variadic macros,
  and GNU extensions (statement expressions, __attribute__, inline asm).

  The machine is 32-bit: int, long and pointers are 4 bytes, short 2,
  long long 8; char is unsigned (ARM); float and double are IEEE
  (software floating point); there are no near/far pointers - memory is
  flat, and far/near/huge are accepted and ignored.

  A minimal program:
.ex
#include <stdio.h>

int main(void)
{
    printf("Hello, world!\n");
    return 0;
}
.endex

  See also: {Library}, {Headers}, {ARM-DOS}

.topic Headers,#include,include
                             Header files

  C:\TC\INCLUDE holds the headers. The standard ones:
    {stdio.h}  {stdlib.h}  {string.h}  {ctype.h}  {math.h}  {time.h}
    limits.h  float.h  stddef.h  stdarg.h  stdint.h  stdbool.h
    assert.h  errno.h  setjmp.h  signal.h  locale.h
  The DOS ones (as in Microsoft and Turbo C):
    {conio.h}  {dos.h}  {bios.h}  {io.h}  {direct.h}  {process.h}
    malloc.h  fcntl.h
  ARM-DOS's own:
    {armdos.h} (registers, interrupts, ports), sb.h (Sound Blaster)

  #include <file.h> searches the include directories; #include "file.h"
  looks next to the source first.

.topic printf,fprintf,sprintf,snprintf,vprintf
                                printf

  int printf(const char *format, ...);
  int fprintf(FILE *f, const char *format, ...);
  int sprintf(char *buf, const char *format, ...);
  int snprintf(char *buf, size_t size, const char *format, ...);

  Formatted output. Conversions: %d %i (int), %u, %x %X (hex), %o, %c,
  %s, %f %e %g (double), %p, %%; flags - + space 0 #; width and
  precision (%5d, %-10s, %.2f, %*d); l for long. Returns the number of
  characters written.
.ex
    printf("%5d|%-6s|%.2f\n", 42, "ab", 3.14159);   /*    42|ab    |3.14 */
.endex
  See also: {scanf}, {puts}, {stdio.h}

.topic scanf,fscanf,sscanf
                                 scanf

  int scanf(const char *format, ...);
  int fscanf(FILE *f, const char *format, ...);
  int sscanf(const char *s, const char *format, ...);

  Formatted input: %d, %u, %x, %f (float *), %lf (double *), %s (a word),
  %c, %[...]. Pass addresses: scanf("%d", &n). Returns the number of
  items converted, EOF at the end of the input.
.ex
    int age;
    printf("How old are you? ");
    if (scanf("%d", &age) == 1)
        printf("In ten years you will be %d.\n", age + 10);
.endex

.topic fopen,fclose,FILE
                              fopen, fclose

  FILE *fopen(const char *name, const char *mode);
  int fclose(FILE *f);

  Modes: "r" read, "w" write (new/truncate), "a" append, "r+" update;
  add "b" for a binary file. fopen returns NULL if it fails (errno).
.ex
    FILE *f = fopen("NOTES.TXT", "w");
    if (f) {
        fprintf(f, "line %d\n", 1);
        fclose(f);
    }
.endex

.topic dos.h,int86,intdos,REGS,inp,outp,int86x,MK_FP,peek,poke

.topic armdos.h,ARM-DOS
                          ARM-DOS programming

  ARM-DOS is DOS 4.00 on an ARM926 PC. What is different from an x86 PC:

    registers   union REGS fields are 32 bits; segment:offset pairs become
                flat pointers (the offset register holds the address)
    memory      flat: the text screen is at (unsigned short *)0xB8000,
                mode 13h graphics at (unsigned char *)0xA0000
    ports       inp/outp (dos.h) as on a PC: 0x3C8/0x3C9 VGA palette,
                0x61 speaker, 0x60 keyboard
    interrupts  INT n is "svc #n"; int86() does it for you
    code        ARM (32-bit instructions); inline assembler: asm("...")

  armdos.h has the details: struct armregs, _armdos_intr(n, &regs),
  armdos_setvect (interrupt handlers are plain C functions), port access,
  ARMDOS_TEXT_VRAM, armdos_halt() (wait for an interrupt). The samples in
  C:\TC\SAMPLES show mode 13h graphics (MODE13.C), the PC speaker
  (TUNE.C) and inline assembler (ASMDEMO.C).
.ex
#include <dos.h>
#include <conio.h>

int main(void)
{
    union REGS r;
    unsigned char *vga = (unsigned char *)0xA0000;
    int i;
    r.x.ax = 0x13; int86(0x10, &r, &r);     /* mode 13h */
    for (i = 0; i < 64000; i++) vga[i] = i % 320;
    getch();
    r.x.ax = 0x03; int86(0x10, &r, &r);     /* back to text */
    return 0;
}
.endex
